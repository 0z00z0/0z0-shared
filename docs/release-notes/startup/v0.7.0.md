**The first release of the startup component.** `ZeroZero.Startup` owns the application's logon task
in the Windows Task Scheduler and nothing around it: the identity the task runs as, a power-safe
elevated definition, registration, an enabled read cheap enough for a tray menu, enable, disable and
delete, a demand start that proves the task can actually run, and the repair of a task an older build
registered.

## What is in the package

- **`StartupTask`** — read the current state, register, enable, disable, delete, repair, and demand
  start. **Enable and disable refuse when no task is registered** rather than doing nothing quietly,
  because the user asked and a silent no-op leaves the menu lying.
- **`StartupTaskState`** — whether the task exists, whether it is enabled, when it last ran, what it
  returned, and whether it has ever run at all.
- **`TaskIdentity`** — the account name for the trigger and the security identifier for the principal.
  **The scheduler accepts neither in the other's place**, which is the whole reason this type exists.
- **`StartupTaskRepair`** — brings a task an older build registered up to the current definition, over
  delegates, so the decision is testable without a scheduler present.

## Three things to know

**Registering or repairing needs an elevated process.** The scheduler refuses a highest-run-level task
from a standard token.

**The consuming application must not switch on invariant globalisation.** Every write through the
scheduler library then fails with a type-initialisation error while every read keeps working — so the
failure presents as a permissions problem and is not one.

**Demand-start verification is for a task that starts something other than the application itself.**
Demand-starting the application's own logon task just trips its single-instance lock.

## Deliberately not here

**Nothing here creates the logon task**, and repair leaves an absent task absent. The application
manifest, the installer script that registers and removes the task, the gate on where the application
is installed, and any watchdog task all stay with the application.

## What it depends on

`ZeroZero.Primitives` for the log sink, and the Task Scheduler library — **kept out of every public
signature**, so it never reaches a consumer's code. Plain `net10.0`, Windows-only by attribute.

## Why 0.7.0 and not 0.1.0

Every component in the family starts at 0.7.0. Up to and including 0.6.0 one number released every
package together; 0.7.0 and above means a component releases on its own.
