**The watchdog task, which the component previously left with the application.** Additive: the
logon task and every type around it are untouched.

## Why it moves here

A watchdog is the one backstop against any way a process can die, so an application whose session
blocks input or the network depends on it. Two applications keeping their own copy of it drift, and
the copy that is wrong is the one nobody is watching.

## Added

- **`WatchdogTask`** — the task by name. `Ensure()` writes it where it is absent or has drifted,
  leaves a correct one alone, and never throws: it runs at application start, where a throw would
  take the application down over the very task that exists to bring it back. `Delete()` for the
  installer's uninstall. `Hold` is the record of a deliberate exit.
- **`WatchdogTaskOptions`** — name, description, executable, the relaunch argument, the three
  probes' timing, the hold marker's path, the application's check on where it is installed, and the
  log sink.
- **`WatchdogHold`** — `Hold()`, `Release()`, `IsHeld`. A file, because the two sides never share a
  process: the exit is written by the application on its way out and read by the copy the scheduler
  starts afterwards. Every operation is best-effort, and an unreadable marker reads as not held, so
  the failure costs a relaunch rather than leaving the application down for good.
- **`WatchdogEnsure`**, **`WatchdogEnsureResult`** and **`WatchdogEnsureOutcome`** — the decision
  over delegates, testable with no scheduler. `Skipped`, `AlreadyCorrect`, `Registered`, `Failed`.

## What the task looks like

The same principal and power-safe settings as the logon task, with `StartWhenAvailable` on, and
three triggers: a repeating one every five minutes by default; one five seconds after the
workstation unlocks; and one fifteen seconds after Power-Troubleshooter event 1, which the machine
writes when a resume has completed. The unlock and resume probes exist because a process killed
while the machine was locked or asleep would otherwise stay down for a whole interval of active
use.

## Where it differs from the logon task, deliberately

- **An absent watchdog is written.** The logon task's absence is the person's choice and `Repair`
  respects it; the watchdog is the application's own backstop and `Ensure` creates one.
- **A disabled watchdog is repaired**, for the same reason.
- **Nothing about the person's logon choice is consulted.** `Ensure` runs on every start regardless.

## What stays with the application

The single-instance gate that makes a probe finding a live process exit at once; deciding that an
exit was deliberate and calling `Hold()`; the check on where the application is installed, passed
as `RegisterWhen`, because a task pointing at build output starts stale binaries for as long as it
survives; and removing both tasks at uninstall.

## What a consumer on 0.8.0 gets

Nothing it had changes. An application still keeping its own watchdog can adopt this at its own
pace; until it does, the two definitions have to be kept in step by hand, which is the state this
release exists to end.
