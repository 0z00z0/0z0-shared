## A promise that could be broken at start-up

`StartupTaskRepair` promises never to throw. On 0.7.0 it read the current Windows identity **above**
the delegates whose failure is its outcome, so an identity carrying no security identifier threw out
of the repair rather than coming back as a result — taking the application down at start-up over a
scheduled task it never needed to be running. That is the exact hazard the promise exists to
prevent.

The read moves inside the rewrite delegate, where it is used, so its failure is carried on the
outcome. The state logged afterwards is guarded: that line is not part of the answer.

## The one thing that still throws, and is meant to

A null delegate is an argument error, not a repair failure, and `StartupTaskRepair` still refuses
one. The guide called that "nothing throws"; it now says which is which.

## A platform floor the project never declared

The guide's platform row claimed Windows 10 1809. The project targets plain `net10.0` and declares
`SupportedOSPlatform("windows")` with no version, so no floor above Windows itself is asserted
anywhere. Corrected in the guide.
