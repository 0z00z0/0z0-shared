**The tray packages move to .NET 11 and Windows App SDK 2.7.0, and a failed start explains itself in one log line.**

**Released** 2026-11-19

**Minor, breaking.** The WinUI package targets `net11.0-windows10.0.26100.0` instead of `net10.0-windows10.0.26100.0` and `ZeroZero.Tray` `net11.0` instead of `net10.0`, and the Windows App SDK under them moves from 2.4.0 to 2.7.0. Takes `ZeroZero.Win32` 0.10.0, `Microsoft.Win32.SystemEvents` 11.0.0 and `H.NotifyIcon.WinUI` 2.4.1.

## Added

- **`TrayStartupResult.Explanation`**, one plain line for the log, null when the icon was created.
  It says what failed, the likely cause (the taskbar or the notification area was not ready yet),
  that the application is expected to try again or be restarted, and the last refusal's message
  and error code. The notify-icon library's own refusal carries no Win32 code, and the line says so.

## What a consumer has to change

- Target `net11.0-windows10.0.26100.0`, which the build kit's application block at 0.10.0 sets, and
  build with the .NET 11 SDK, 11.0.100 or later.
- **The Windows App SDK moves from 2.4.0 to 2.7.0.** An unpackaged application needs
  `Microsoft.WindowsAppRuntime.2` at 2.7.0.0 registered for the user; an installer that carries the
  runtime, and any prerequisite check written against 2.4.0, move to 2.7.0 with it. A self-contained
  publish carries the runtime in its own folder.
- A direct reference to a component named above rises to at least the version named, or the restore
  fails with `NU1605`.
- Raise `ZeroZero.Build` to 0.10.0 in the same change where the application takes the build kit.
  The kit pins the packages named above; an older kit pins them below what this release needs, and
  the restore fails with `NU1605`.
- **The .NET 11 desktop runtime is required on the end user's machine** for a framework-dependent
  application; a self-contained publish carries it.
- Log `Explanation` where the application logged `Outcome`, `Attempts` and `Elapsed` itself, and
  report a start that gave up without an exception: a shell that was not ready is not a defect in the
  application. Optional; the other members are unchanged.
