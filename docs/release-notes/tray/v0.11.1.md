**A failed start or render leaves the tray host ready to try again, and the default menu theme
leaves the application's choice alone.**

**Released** 2026-10-11

**Patch.** Nothing a consumer compiles against moves. Takes `ZeroZero.Win32` 0.9.2.

## Fixed

- An icon, tooltip or menu delegate that throws during `Start()` throws to the caller and leaves the
  host not started, so it can be started again.
- The startup retry lets `ObjectDisposedException` out instead of counting a disposed host as a
  refusal by the shell.
- A render is recorded only once the icon has loaded, so a failed render is retried at the next
  reconcile.
- `CurrentRequest` is null after `Dispose`, as its summary says.

## Changed

- `MenuTheme` set to `ElementTheme.Default` makes no call, so the process's menu mode stays whatever
  the application set, or Windows' own where it set none. Light and Dark go through
  `DarkChrome.Apply`, which reports false rather than throwing where `uxtheme.dll` is missing.
