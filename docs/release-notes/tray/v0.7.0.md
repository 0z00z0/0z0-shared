**The first release of the tray icon component.** Two assemblies under one number.
`ZeroZero.Tray` is the plain half: the icon file an application writes for its notification icon, the
size the taskbar will draw it at, and whether that taskbar is light or dark. `ZeroZero.Tray.WinUI` is
the host that owns the icon in a running WinUI application — its lifecycle, the listeners that notice
a theme, display or shell change, the rendered-file cache, the tooltip, click classification and the
menu refresh.

**What the icon looks like stays with the application.** This component asks for an image at a size,
a theme and a stroke tone, and takes what it is given.

## What is in the package

The plain half: **`IcoFile`** builds and writes an icon file from PNG frames, filling each directory
entry from the PNG's own header rather than from a size the caller claims — a frame that is not a
PNG, has a side of zero or over 256, or repeats another frame's size is refused with the reason.
**`TrayIconSlot`** gives the pixel size for a scale or for the current taskbar. **`TaskbarThemes`**
reads whether the taskbar is light or dark and what stroke tone suits it.

The host: **`TrayHost`** with **`TrayHostOptions`** — a name, a function that produces the image, and
optionally a tooltip, a menu, click handlers and a cache directory. **`TrayTooltip`** composes lines
into the shell's cap. **`TrayMenuItem`** covers commands, toggles and separators.
**`TrayClickPolicy`** classifies a click into open, toggle or nothing.

## Four things to know

**Efficiency mode is refused, deliberately.** The notify-icon library arms it for the whole process by
default — idle priority and power throttling, applied once and never restored — which throttles
everything else the application is doing. The host switches it off.

**The icon's name must stay stable across versions.** The shell keys the user's show-or-hide choice on
it, so changing it makes every build a new icon the user has to un-hide again.

**A tooltip is capped at 127 units.** A line that does not fit is cut before its suffix with an
ellipsis, so a reading keeps its number; a line that could not fit at all is dropped along with
everything after it; and a cut never lands between the halves of a surrogate pair.

**A pop-out that hides when it loses focus needs telling.** Call `NotePopOutDismissed` from its
deactivation, or the mouse-up that dismissed it reopens it.

`Start` runs once, on the user-interface thread, after the XAML runtime is up, and says so rather than
failing obscurely.

## What it depends on

`ZeroZero.Tray` takes `ZeroZero.Win32` and nothing else, and targets plain `net10.0` — Windows-only by
attribute, not by framework. `ZeroZero.Tray.WinUI` adds the Windows App SDK, the notify-icon library
and the system-events package. **No library type reaches a public signature.** The notify-icon pin is
a ceiling for a consumer's own direct reference to it.

## Why 0.7.0 and not 0.1.0

Every component in the family starts at 0.7.0. Up to and including 0.6.0 one number released every
package together; 0.7.0 and above means a component releases on its own.
