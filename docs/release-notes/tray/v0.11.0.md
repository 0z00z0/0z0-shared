**A host that cannot derive from `TrayHost` gets the same shell wait and retry, through plain
callbacks.**

**Released** 2026-10-10

**Minor.** A member is added. Nothing an application already calls behaves differently.

## Why

`TrayStartup.StartAsync(host, options)` only takes a `TrayHost`. A host built on its own
`TaskbarIcon` — several icons, a menu `TrayHost` cannot express — could not reach the shell-wait
and retry behaviour without rewriting onto `TrayHost` first.

## Starting a host that is not a `TrayHost`

`await TrayStartup.StartAsync(create, abandon, options)` runs the same wait-for-the-taskbar and
retry-the-icon sequence as the `TrayHost` overload, from two callbacks instead of a host:

- `create` offers the icon; it is retried up to `CreateAttempts` times the same way.
- `abandon` removes whatever `create` left behind once the attempts run out.
- There is no `prepare` step. A caller with preparation work does it inside `create`.

[`zerozero-tray.md`](../../zerozero-tray.md) has the wiring, under "Starting at sign-in".

## What a consumer has to change

Nothing is required. A host that cannot use the `TrayHost` overload can now reach the same
behaviour through this one.

## Unchanged

The `TrayHost` overload behaves exactly as before. Both tray assemblies release under the same
number.
