**The first release of the lifecycle component.** `ZeroZero.Lifecycle` keeps a tray application one
process that comes back: the single-instance lock held for the life of the process, the
deliberate-exit mark, an automatic relaunch on any other clean exit under a sliding-window limit, and
the per-user data folder every other file hangs off.

It is armed before any window, tray icon or message pump exists.

## What is in the package

- **`ProcessLifecycle`** — `Arm()` puts the exit hook in place; `MarkDeliberateExit()` says this one
  was asked for. Anything else clean brings the process back.
- **`SingleInstanceLock`** — a named mutex taken for the life of the process. An abandoned mutex
  counts as taken, and asking twice under different names is refused rather than quietly answered.
- **`RelaunchLimiter`** — three relaunches in ten minutes, and then it stops. **The count is on
  disk**, because the process keeping it is the one that keeps dying.
- **`Relaunch`** — the argument a relaunched process is started with, and the settle delay before it
  is.
- **`ProductDataPath`** — the roaming per-user folder, created on first ask, and paths under it. A
  rooted path is refused rather than silently escaping the folder.
- **`RelaunchDecision`** names the four outcomes the hook logs, so a log says which one happened.

## Three traps worth knowing before wiring it

**`Arm()` goes before the lock, not after.** A second instance that finds the lock held exits — and
that exit must reach the hook to be marked deliberate, or the hook treats it as a crash.

**A second instance must mark its exit deliberate before returning.** Otherwise its own armed hook
starts a third, which finds the lock held, and so on.

**Take the mutex on a thread that lives as long as the process.** A thread that ends while owning it
abandons it, and the next instance sees a lock nobody holds.

## What it deliberately does not cover

**A crash never reaches the hook.** The runtime raises no exit event for an unhandled exception, so
this component covers the clean exit nobody asked for. The crash belongs to the diagnostics component
and to the application's own watchdog.

It also does not decide what counts as deliberate, what the mutex is called — that is the installer's
identity — what the product is called, or how long to wait per kind of launch. All four are the
application's.

## What it depends on

`ZeroZero.Primitives` for the log sink, and the system-events package for the signal that the Windows
session is ending, which a plain `net10.0` target has no other way to hear. Plain `net10.0`,
Windows-only by attribute.

## Why 0.7.0 and not 0.1.0

Every component in the family starts at 0.7.0. Up to and including 0.6.0 one number released every
package together; 0.7.0 and above means a component releases on its own.
