The first tagged release of `0z0-shared`, the shared library behind ZeroZero Software's desktop
applications. It exists so a consumer can pin a readable version instead of a raw commit SHA.

## Pre-1.0 — read this before pinning

**The public API is not stable, and this release lands immediately after a set of breaking
changes.** While the major version stays `0`, a **minor** bump may break the API and a **patch**
never does. Tags are cut on a consumer-visible API change, not on a calendar.

A consumer with code written against the shape that preceded this release does not compile against
it. Every difference is a compile error or a topic move, never a silent behaviour change, and all
of them are tabulated in [the MQTT module's interface document](https://github.com/0z00z0/0z0-shared/blob/v0.1.0/docs/zerozero-mqtt.md) under
**Differences from an earlier shape** — five tables, covering assemblies and namespaces, the entity
model, the wire, the core, and the panel. That section is the migration reference; nothing is
restated here.

The single largest move: discovery publishes **one retained device document** at
`<prefix>/device/<deviceId>/config` rather than one retained config per component, and every entity
carries **one bare topic with a plain value** — no shared payload and no `value_template` anywhere.
A receiver on Home Assistant older than 2024.11.0 never subscribes to the device topic and sees no
entities at all.

On the brand side, `BrandAboutOptions.OnCheckForUpdates` and `OnBeforeExit` are `Func<Task<bool>>`.
Both report whether the host acted, so the window can decide what follows.

## What is in the release

Two modules, six shipping assemblies, one shared version. `Directory.Build.props` declares that
version once and every assembly reports it; the release workflow refuses a tag that disagrees with
it.

**The brand module** — the studio's visual identity and About plumbing.

| Assembly | Target | Holds |
|---|---|---|
| `ZeroZero.Brand.Core` | `net10.0` | Brand constants (name, tagline, palette, links), `AboutInfo`, the console banner |
| `ZeroZero.Brand.WinUI` | `net10.0-windows10.0.26100.0` | `BrandAboutWindow` for a tray app, `BrandAboutControl` for a hosted page, and the brand typeface as content |

**The MQTT module** — four assemblies that put a Windows desktop application on an MQTT broker and,
above that, into a discovery-aware receiver as one device with entities.

| Assembly | Target | Knows about |
|---|---|---|
| `ZeroZero.Config` | `net10.0` | Atomic JSON files, snapshot reads, mutation under one lock, quarantine of an unreadable file |
| `ZeroZero.Mqtt` | `net10.0` | Topics, payloads, QoS, retain, the Last Will, transports, endpoint search, certificate trust, command routing, publish groups |
| `ZeroZero.Mqtt.Discovery` | `net10.0` | Entities, component types, the device document, availability, eviction |
| `ZeroZero.Mqtt.WinUI` | `net10.0-windows10.0.26100.0` | The settings panel a host embeds |

The dependency runs one way, and a consumer takes one project reference: `ZeroZero.Mqtt.Discovery`
brings the core and the settings assembly transitively, `ZeroZero.Mqtt.WinUI` brings the panel as
well. `ZeroZero.Mqtt.Discovery` is WinUI-free, so an entity table composes in a plain `net10.0`
test project with no broker and no desktop present. No `MQTTnet` type reaches a public signature.

## Requirements

.NET 10 SDK. Windows 10 1809 (build 10.0.17763) or later with the Windows App SDK for the WinUI
assemblies; `ZeroZero.Brand.Core`, `ZeroZero.Config`, `ZeroZero.Mqtt` and `ZeroZero.Mqtt.Discovery`
are plain `net10.0` and portable in isolation. The MQTT module requires an MQTT 5.0 broker and, for
discovery, Home Assistant 2024.11.0 or later.

## How to consume it

There is no NuGet feed: neither `ZeroZero.Brand.WinUI` nor `ZeroZero.Mqtt.WinUI` can be packed —
both compile XAML to binary form, and the panel additionally indexes a `.resw` into a `.pri`, none of
which `dotnet pack` carries — so this release is the tag and these notes — which is all a `ProjectReference` on a pinned checkout needs. Pin `v0.1.0` as the
`ref` of the consumer's second `actions/checkout`, or as `--branch v0.1.0` on a sibling clone.
[Pin a tag](https://github.com/0z00z0/0z0-shared/blob/v0.1.0/README.md#3-pin-a-tag) in the README carries both shapes, the MSBuild property
that lets CI redirect the reference, and the item-glob exclusions a workspace-subfolder checkout
needs.

## Verified

640 unit tests across `ZeroZero.Brand.Core`, `ZeroZero.Config`, `ZeroZero.Mqtt` and
`ZeroZero.Mqtt.Discovery`, all passing on `windows-latest` in Release. The release is gated on
them.
