**The panel no longer touches the network while its fields are being edited**, the connection check
reports its outcome instead of its attempts, and a running application can now say which build of
the module it actually loaded. **A consumer holding screenshots of the panel, or a translation of
its strings, is affected** — the string changes are listed key by key below.

**Minor rather than patch.** Behaviour changed, one public enum member is removed and one public
type is added.

## Probing happens on Test connection and Apply, and at no other time

**This is in this tag.** Editing a broker field starts no network operation of any kind.

Until now a field settling started a debounced endpoint search about 700 ms after typing stopped.
The panel already promised that opening the settings page touches no broker; that promise now holds
equally while the fields are being typed into.

- `MqttProbeTrigger.BrokerSettingChanged` is **removed**. The enum is now `TestConnection` and
  `Apply` — both button presses. `MqttEndpointPlan.ShouldProbe` accepts those two and nothing else.
- The panel's 700 ms settle timer and the scheduling behind it are gone. An edit still abandons a
  check already in flight, because its answer is about values that have since moved.
- **A consumer that reads `MqttProbeTrigger` recompiles with an error** if it names the removed
  member. Nothing else in the public surface moved.

Nothing was left stranded by the removal: the progress line, the spinner and the `Looking for the
broker` connection status are all still reached, by the two buttons that remain.

## The connection check reports the outcome, not the attempts

Found by review at `v0.4.0` — read from the source, not observed in a running application. A
screenshot showing the failure came from a different consumer on an older build and was relayed
without a version, so it was not evidence for this tree; the defect turned out to be live here as
well.

A successful check composed a sentence like

> Connected over WebSocket. The broker accepted these settings. TCP could not be reached (nothing
> answered on that port).

Three faults. A failed leg of an internal search sat directly under a success, where a reader scans
it as a fault to investigate. *The broker accepted these settings* restated *Connected*. And
*nothing answered on that port* explained the mechanism of a non-event.

The rule is now that the answer to "does this work" is the outcome plus the working configuration:

| The run | What it says |
|---|---|
| connected | `Connected over WebSocket on port 443.` |
| the broker answered and refused | that verdict alone — a rejected credential is the whole finding |
| nothing answered anywhere | what was tried and what each did, de-duplicated |

Failures still matter where nothing succeeded, which is the case a reader needs them for.

- `ReportWithContext` is **removed**; `ReportConnected` is **added**, and carries the port.
- `ProbeSuccess` is now `Connected over {0}.` — the restatement is gone.
- `ReportNothingReached` is `The broker was not reached. {0}.` It previously said *Neither transport
  reached the broker*, which is false when a transport is pinned by hand and only one is tried.
- `MqttPanelText.Describe(MqttProbeReport)` keeps its signature; what it composes changed.

## The module reports which build is running

`MqttModule.Version` is the module's version **as the loaded assembly carries it**, in the shape
`0.5.0+1a2b3c4`.

It is reflected off `AssemblyInformationalVersionAttribute` rather than compiled in from
`Directory.Build.props`. That is the point rather than an implementation detail: a consumer builds
against a sibling working tree rather than the revision its pin names, so a value that cannot
disagree with the pin answers nothing. The commit half comes from `SourceRevisionId`, stamped at
build time from `git rev-parse`; a tree with no git available reports the bare number.

- **A host reads it as a property** — `MqttModule.Version` — with no dependency on the panel.
  `MqttModule.Read(assembly)` answers the same question for any assembly, so a host can report its
  own build beside it.
- **The panel shows it with no host action**, appended to the publish switch's info icon. Version
  information conventionally lives in an About box, and nobody opens one while chasing a broker that
  will not connect; that icon is in front of the reader at the moment the question arises. It rides
  whatever text is in force, so supplying `MqttPanelSetup.PublishInfo` does not drop it.

## The copy pass

What this tag carries, by key.

**Corrections — these were wrong, not merely wordy:**

| Key | Was | Now |
|---|---|---|
| `ProbeTlsUntrusted` | pointed at "the certificate trust setting" | the reason alone. **There is no such field on the panel** — trust is configured by the host in code, so the advice sent a reader looking for a control that does not exist |
| `RowLastCommand` | `Last command received` | `Last command accepted`. A command is recorded on acceptance, so a refused one never appears; the label claimed otherwise and its own info icon contradicted it |
| `InfoDeviceName` | "Saved as it is typed" | "Saved when the box is left, not on Apply" — which is what the code does |
| `DescDiscoveryPrefix` | "Change only to match the broker" | "…for a consumer that listens elsewhere". The prefix is a consumer's concern, and this row's description contradicted its own info icon |
| `DeviceIdWarning` | "stops resolving" | "stops working" — the acknowledgement two paragraphs down already said that for the same fact |

**The acknowledgement checkbox**, which is the only sentence a user must actively agree to:

> I understand that anything using the old ID stops working, and its recorded history is not carried
> over.

It previously read *I understand everything referring to the old ID stops working* — which parses
briefly as "I understand everything", confirms comprehension rather than consent, and omitted the
second irreversible consequence the dialogue body raises.

**Structural — three habits produced most of the rest:**

- **The Apply rule was stated four times on one panel.** It is now stated once, in `DescApply`,
  which is always on screen: *Saves every broker field above and reconnects once. Nothing above is
  live until then.* `InfoApply` is **removed** with the Apply row's info icon, and `InfoBroker`,
  `InfoPublishSwitch` and `InfoTest` no longer repeat it.
- **The endpoint cache key had leaked into three tooltips.** It is gone from `InfoPassword`, where
  it was appended to a privacy assurance and invited the reader to wonder what it meant for their
  password, and from `InfoConnection`. `InfoUsername` keeps the one consequence that is the user's:
  changing the username starts the search again.
- **The panel explained its own design.** "which is why this row says which it is", "rather than
  riding the Apply batch" and "the rest of this panel is hidden because none of it applies" are all
  gone.

**Reworded, same facts, fewer words:** `InfoStatus`, `InfoConnection`, `InfoBrokerInUse`,
`InfoLastPublish`, `InfoLastCommand`, `InfoDevice`, `InfoDeviceId`, `InfoBroker`, `InfoHost`,
`InfoPort`, `InfoTransport`, `InfoEncryption`, `InfoUsername`, `InfoDiscoveryPrefix`,
`InfoPublishSwitch`, `ProbeAuthRejected`, `ProgressNoAnswer`.

`InfoEncryption` was the worst string on the panel — five sentences, three of them the fallback
algorithm transcribed, using "clear text", "in clear text" and "plain" for one idea. The reader's
actual question is whether Automatic can silently drop them to clear text, and that is now the first
sentence.

`InfoDeviceId` previously restated the description above it. It now carries the character rules,
which nothing else on the panel stated.

**Vocabulary:** "commits" is gone from the Apply and Test text — the same version-control register
as the already-banned *staged*. "Front door" and "front-door ports", invented in `InfoPort` and
reused in `InfoEncryption` without ever being defined, are gone. "An explicit choice is never
reached around" appeared twice and is not an idiom; it is now "always used".

**Punctuation:** `Applied` and `Saved` lose their full stops, matching `Not applied` beside them.

### The last English literals moved into the resource table

The info icons' screen-reader names and the device-id validation messages were literals in code, so
a translated panel still named its icons in English to the one audience that depends on the naming.
They are now keys: `Subject*` for the icons, `DeviceIdTooLong` and `DeviceIdNoAlnum` for the
validator.

`MqttIdentity.Validate` gains an optional second parameter — `Validate(string raw, MqttStrings? text
= null)`. Existing call sites compile unchanged and get the module's own en-GB.

### Deliberately not in this tag

- **No certificate-trust control on the panel.** `ProbeTlsUntrusted` stopped pointing at one rather
  than one being added; the setting remains a host's to configure through `MqttSettings`.
- **The row descriptions other than Apply and Discovery prefix** were not re-audited — `DescPort`,
  `DescTransport`, `DescEncryption`, `DescUsername`, `DescPassword`, `DescDeviceName`, `DescDeviceId`
  and `DescPublishSwitch` stand as they were.
- **Nothing a host owns** — `PublishTitle`, `PublishDescription`, `PublishInfo`, `PublishGroupsInfo`
  and `DeviceIdConsequence` are the consumer's copy and are untouched.
