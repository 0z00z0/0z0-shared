**The live connect is bounded, the reconnect loop survives a settings change, and six unused public
members are removed.**

**Released** 2026-09-29

**Minor, and it breaks.** Six public members are removed, with no replacement shim.

## Removed

- `DiscoveryTopics.DeviceIdOf`, and the ledger fallback it served.
- `MqttEntitySet.Withheld`. `Resolve` answers the same question.
- `MqttChannelSet.HasPublished`.
- `MqttEndpointPlan.DescribeProvenance`.
- `MqttEndpointPlan.AutomaticallyDetected`.
- `MqttEndpointPlan.SetManually`.

## Fixed

- The live connect carries `ConnectTimeout` in a linked cancellation token. MQTTnet ignores its own
  timeout option for a cancellable token, so a stalled handshake held the maintain loop
  indefinitely.
- Only the loop's own cancellation ends the reconnect loop. An expired connect budget or a
  cancellation raised inside MQTTnet counts as a failed attempt, so a settings change during a
  connect no longer stops reconnecting for good.
- A settings change while running goes through the loop: the loop drops the socket on its own thread
  and resets the backoff, whether the link is up or down.
- The birth-message republish delay runs off the shared command worker, which was blocked for up to
  30 s.
- The test broker's retained-payload record follows the retain flag, so a clear sent without it no
  longer reads as cleared.
- `MqttText.Pattern` documents that `Accept` does not apply it.
- Comments, tests and the MQTT guide state current behaviour; the guide's name-mapping chapter is
  gone.
