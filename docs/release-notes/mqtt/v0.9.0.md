**The settings panel can be handed the live connection itself, and then needs no code of the host's
to describe it.** Apply also stops repeating a connection test that has just passed on the same
values.

**Released** 2026-09-28

**Minor, and nothing breaks.** A setup written for 0.8.1, with all four connection members set by
hand, compiles and behaves exactly as before. The shorter form is added beside it.

## What a host supplies

Before this release a host wrote one line of its own for each of four members, every one of them
only passing on something the connection already knew:

| Member | Written by the host on 0.8.1 |
|---|---|
| `Activity` | `connection.Activity` |
| `ConnectionState` | `() => connection.State` |
| `PublishNow` | `() => connection.PublishNowAsync()` |
| `RecallEndpoint` | an accessor over the host's own copy of the endpoint memory — optional, and easily left out |

With `new MqttPanelSetup(connection)` the host writes none of the four. Each is read from the
connection at the moment a row is drawn: `Activity` is the connection's own instance,
`ConnectionState` reads `State`, `RecallEndpoint` reads `RememberedEndpoint`, and `PublishNow` calls
`PublishNowAsync()`. What stays with the host is what the module cannot know: the settings store,
the publish groups, the topic root, the two change callbacks, and the optional copy.

This closes a contradiction on the Status block. A setup with `RecallEndpoint` left out showed the
Connection row reading the live link while the Broker in use row read "not connected yet" and the
closed Broker line read Automatic for the port, the transport and the encryption — each row true
about a different source. Built from the connection, all three describe the same link.

Any of the four set in the object initialiser as well replaces the connection's.

## Setting the four by hand

The parameterless constructor stays for a host with no `MqttConnection` to hand. `Activity`,
`ConnectionState` and `PublishNow` are no longer `required`, so the compiler no longer catches a
missing one: **`MqttSettingsPanel.Initialise` throws an `ArgumentException` naming the first one
unset**, before anything is drawn. `RecallEndpoint` stays optional.

## Apply and the connection test

Before this release Apply opened a throwaway connection every time, even straight after Test
connection had passed on the values being applied. It now shows that pass again and opens nothing,
when the newest
test — from Test connection or an earlier Apply — passed on exactly the same host, port, transport,
encryption, username, password, certificate trust and device id. Any one differing, or a newest
test that failed, and Apply tests as before. Test connection always tests.

`MqttProbeSession` carries the rule for a host drawing its own form: `Start(target)` records what a
run tests, and `TryReuse(trigger, target)` answers whether Apply may show the last pass instead of
starting another. `Start()` with no argument still compiles and remembers nothing; a caller built
against 0.8.1 recompiles unchanged.

## Unchanged

The Status rows' wording, the closed-section lines, the endpoint search, the connection itself, and
`ZeroZero.Mqtt.Discovery`.
