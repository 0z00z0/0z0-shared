**Opening the settings panel no longer crashes the application when the application's own resources hold an MQTT text the module cannot format.**

**Released** 2026-10-23

**Patch.** Nothing a consumer compiles against moves. Takes `ZeroZero.Primitives` 0.9.1,
`ZeroZero.Config` 0.9.0, `ZeroZero.Controls.WinUI` 0.11.0 and `MessageFormat` 8.0.0.

## Fixed

- A host text the module's arguments cannot fill is ignored in favour of the module's own text, in
  the panel and in `MqttPanelText` alike. This covers a positional `{0}` under one of the four
  counted keys (`AgeMinutes`, `AgeHours`, `AgeDays`, `SummaryPublish`), which take named ICU
  arguments, and an ICU or malformed pattern under a key that takes positional arguments, whether
  it comes from `MqttPanelSetup.Strings` or the application's `.resw`.

## Added

- `MqttPanelText(host, log)`: the log is told once per key when a text cannot be formatted. The
  panel passes `MqttPanelSetup.Log`.

An application whose log names a key here corrects that text to the module's arguments, or deletes
it if it is only a copy of the module's own.
