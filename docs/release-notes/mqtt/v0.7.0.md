**The module's own logging interface is gone**, a host's wording of a panel string finally wins over
the library's, and the settings panel no longer brings the studio's brand assemblies with it.
**A host that implements `IMqttLog` will not compile** — the fix is one interface name and one
`using`, and the method bodies are untouched.

**Minor rather than patch.** Two public types are removed and one changes namespace.

## Breaking: `IMqttLog` and `NullMqttLog` are removed

The module had its own two-member logging interface. The same two members are now the family's shared
log sink, so a host wiring up several components implements one interface rather than one per
component.

What a consumer does:

- Change the implemented interface from `ZeroZero.Mqtt.IMqttLog` to `ZeroZero.Primitives.ILogSink`.
  **The two members are identical in name and signature**, so nothing inside the implementation
  changes.
- Replace `NullMqttLog.Instance` with `NullLogSink.Instance`.
- Add `using ZeroZero.Primitives;`.

**Nothing has to be added to the project file.** `ZeroZero.Primitives` already arrives with every MQTT
assembly.

The interface briefly existed as an alias of the shared sink so that an existing implementation kept
compiling. It earned nothing — both consuming applications are pinned to an older revision and discard
superseded code when they adopt — so it is removed rather than left as a permanent redirection.

## Also moved: `CoalescingGate`

The burst-collapsing gate is now `ZeroZero.Primitives.CoalescingGate`. Same name, same three members,
new namespace. **It appears in no public signature anywhere in the module**, so a consumer that only
used the module's own API sees nothing; one that borrowed the gate for its own debouncing changes a
`using` and nothing else.

`MqttModule.Read(Assembly)` is removed for the same reason — the shared assembly-version reader does
the job. **`MqttModule.Version` stays** and still answers which build of the module is loaded.

## A host's own wording now wins

**Declaring a module string's key in your own resource file now actually overrides the library's
text.** It did not before: the panel asked the library's own resource map first, so the library
always answered first and a consumer's translation or re-wording was silently ignored.

The order is now a host's map, then the library's copy, then the library's root, and it lives in one
place — `MqttResourceMaps.Subtrees` in the plain assembly — rather than being spelled out at the point
of use. A key nobody answers still falls back to the module's built-in en-GB, so a panel never renders
blank.

## The panel no longer brings the brand assemblies

The settings panel used one control from `ZeroZero.Brand.WinUI` — the info bubble — and took the whole
brand component, typeface and About window included, to get it. That control now lives in
`ZeroZero.Controls.WinUI`, which carries no studio identity, and the panel references that instead.

**On the package route this is a new package to acquire**: `ZeroZero.Controls.WinUI` at 0.7.0. What
you no longer acquire is `ZeroZero.Brand.Core` and `ZeroZero.Brand.WinUI` — an application that wants
the About control now references the brand component deliberately.

**`ZeroZero.Win32` still arrives transitively**, through the controls assembly.

## `Cancel()` belongs on the window's close, not on leaving the page

`MqttSettingsPanel.Cancel()` is final. Under a settings shell that keeps every page and shows it
again, calling it when the user navigates away leaves a dead panel for the next visit. **A host that
calls it from a page-leave hook must move the call to the window's `Closed`.**

Nothing changed in the method; what changed is that the rule is now stated where a host will read it.

## Taking it

Three packages: `ZeroZero.Mqtt` and `ZeroZero.Mqtt.Discovery` on `net10.0`, `ZeroZero.Mqtt.WinUI` on
`net10.0-windows10.0.26100.0`. All three release together under one tag and one number. The MQTT
client library remains the only third-party dependency, and no type of it reaches a public signature.

Taking `ZeroZero.Mqtt.WinUI` brings the whole module, and now also `ZeroZero.Primitives`,
`ZeroZero.Config`, `ZeroZero.Controls.WinUI` and `ZeroZero.Win32`, each at 0.7.0.
