**The rule that decides whose wording a panel renders is now executed by a test rather than modelled
by one**, and the order the two resource indexes are opened in is stated where that test can reach
it. Three additions to one type; nothing else moves.

**Patch.** Nothing is removed or renamed, no member changes signature, and the strings a panel
renders are the same ones 0.7.0 rendered. A consumer that changes no code sees no difference at
runtime.

## What was covered, and what was not

A host's own `.resw` entry for a module key outranks the library's copy. That precedence is two
orders, not one: which index is opened first, and which subtree is asked first under it.

On 0.7.0 only the subtree order lived in `MqttResourceMaps`, in the plain `net10.0` assembly. The
index order was two hard-coded calls inside `MqttResourceStrings`, which targets Windows and cannot
be loaded where the tests run — so the test that claimed to cover precedence rebuilt the walk in its
own code and asserted against the rebuild. A walk that drifted from the one shipping would have
passed.

`MqttResourceMaps` now states both orders and owns the walk itself. `MqttResourceStrings` does
nothing but open what it is named and read what it is asked. The test drives the shipping walk over
probes it supplies, so the assertions are about the code the panel runs.

## Three members added

- `MqttResourceMaps.ApplicationIndex` — the empty name that means the index the application already
  has, which opens by asking for no file at all.
- `MqttResourceMaps.Indexes(library)` — the indexes to open, host-owned first: the application's
  merged index, then `<library>.pri` beside the executable. Both answer a module key under the bare
  map name, so this order alone decides which wording is rendered.
- `MqttResourceMaps.Find(key, probes)` — the first non-empty answer from the probes in the order
  given, or null. A probe that throws counts as a place without the key, and an empty answer counts
  as no answer, so a blank entry cannot blank a control the built-in text fills.

A host with a resource system of its own can build an `IMqttStringSource` over `Find` and get the
module's precedence without reimplementing it.

## Unchanged

The precedence itself, in both orders. The empty-answer and throwing-probe rules. The subtree list.
`MqttResourceStrings.Instance` and its fallback to the built-in en-GB when no index can be opened.
`ZeroZero.Mqtt.Discovery` and `ZeroZero.Mqtt.WinUI` carry no other change.
