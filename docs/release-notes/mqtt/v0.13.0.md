**Every superseded device id is evicted, a removal holds off a concurrent apply, and the Test and
Apply decision is one call.**

**Released** 2026-10-11

**Minor, additive.** One method and one enum are added. Takes `ZeroZero.Primitives` 0.8.0,
`ZeroZero.Config` 0.9.0 and `ZeroZero.Controls.WinUI` 0.10.0.

## Added

- **`MqttProbeSession.Decide(trigger, validation, publishingEnabled, target)`** answers a
  **`MqttProbeDecision`**: `Unusable`, `NothingToProbe`, `Reused` or `Run`, checked in that order.
  Test connection refuses with a reason on the probe line; Apply refuses silently. The settings
  panel uses it.

## Fixed

- A device id changed twice while the link was down evicts the retained topics of both earlier ids.
  Only the latest was evicted, and the first id's topics stayed on the broker. The id in force is
  never evicted, so an id that comes back keeps its topics.
- `MqttConnection.RemoveDeviceAsync` and the teardown's stop take the reconcile gate. An apply during
  a removal re-enabled publishing and refilled the topics being emptied.
- Revert in the settings panel abandons a connection check in flight, which otherwise reported its
  answer under the reverted fields.
- A whitespace-only publish title, description or info from the host, and a whitespace-only
  translation, fall back on the module's own text, as an empty one does.
- A publish group's info icon has its screen-reader name in the module's strings, so a translated
  panel no longer reads it in English. `InfoSubject` keeps its en-GB text.

## Changed

- Every failure the connection logs is one line in the form `MqttProbe.Describe` gives, without an
  exception object.
- `DiscoveryPublisher.RemoveDeviceAsync` withdraws the device without stopping the connection, so
  the channels refill the emptied topics. Its summary and the guide say to call
  `MqttConnection.RemoveDeviceAsync` to remove a device.
