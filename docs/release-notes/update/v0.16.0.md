**An application holds an install through one `InstallHolds`, asked on the unattended and the manual
path alike.**

**Released** 2026-10-12

**Minor, breaking.** `UnattendedUpdateOptions.MayInstallNow` is removed, and an entry assembly that
reports a pre-release version makes the `UpdateService` constructor throw. Takes
`ZeroZero.Primitives` 0.8.0, `ZeroZero.Win32` 0.9.2, `ZeroZero.Controls.WinUI` 0.10.0 and
`ZeroZero.Brand.WinUI` 0.12.2.

## Added

- **`InstallHolds`**, what the application has going on that no installer may interrupt.
  `Hold(string reason)` holds until the returned object is disposed; `Hold(Func<string?>)` holds
  while the function returns a reason, and is asked every time. The first hold in registration order
  gives the reason. A function that throws or returns a blank string holds with
  `InstallHolds.Unreadable`, and a throw is logged once per hold. A hold never stops a download or an
  installer already running.
- **`UnattendedUpdateOptions.Holds`**, asked after the machine-free rule and immediately before the
  installer starts. A hold refuses that attempt with one log line per reason; the next tick asks
  again.
- **`UpdateFlowOptions.Holds`**, asked before the install question and again immediately before the
  launch. A hold answers **`UpdateFlowResult.Held`**: nothing starts, shutdown is not called, and a
  verified download is discarded.
- **`IUpdatePrompts.SayHeldAsync(release, reason)`**, with a default that takes whatever is on
  screen away and says nothing. `UpdateWindowPrompts` shows `UpdateMessages.HeldHeadline` and
  `UpdateMessages.HeldText`. A scheduled run held before the question says nothing.

## Fixed

- A failed unattended download keeps its release, which is tried again on the next tick under either
  cadence, `CheckCadence.Once` included. A download that did not verify, or a release that cannot be
  verified, is let go.

## Changed

- The running version read from the entry assembly follows the release tag's rule once the commit
  stamp after `+` is dropped. A pre-release suffix such as `1.2.3-beta` is refused, and the
  `UpdateService` constructor throws as it does for any unreadable version. A `RunningVersion` set
  in `UpdateOptions` is read as given.
- `UpdateWindow` takes the brand face from the brand component's font dictionary.

## What a consumer has to change

- Applications pass an `InstallHolds` as `Holds` on `UnattendedUpdateOptions` and on every
  `UpdateFlowOptions` instead of `MayInstallNow`; refusing one particular release at install time is
  not possible.
- An application whose assembly version carries a pre-release suffix sets
  `UpdateOptions.RunningVersion`.
