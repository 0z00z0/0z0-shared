**The component now decides when to check and when an installer may start with nobody asked.** An
application switches that on and sets how often a check runs; the rule that the machine has to be
free belongs to the component, and an application refuses a single moment through one call made just
before the installer starts.

**Released** 2026-09-28

**Minor, and nothing breaks.** Everything here is new and optional. An application that wires none of
it behaves exactly as it does on 0.11.0: the three service calls, the scheduler and the flow are
unchanged.

## What the component decides

`UnattendedUpdatePolicy` sits beside the flow and drives it. One tick decides everything:

- **Whether this happens at all.** `UnattendedUpdateOptions.Enabled` is false unless the application
  sets it, so an absent setting installs nothing — and checks nothing, because the policy is the
  whole of that path rather than an install step bolted onto a check.
- **When a check runs.** `CheckInterval`, a day unless the application sets it, counted from process
  start and never persisted.
- **When to try again without waiting for the next day.** The scheduler ticks every
  `RetryInterval`, ten minutes unless the application sets it, and each tick asks what is due. A
  check that did not complete does not stamp the cadence, and an installer that could not start is
  retried on the same tick.
- **Whether the machine is free.** An installer starts only where the screen is locked, or nothing
  has touched the keyboard or the mouse for ten minutes. `UnattendedUpdatePolicy.RequiredIdle` is
  the value and it is fixed: an application refuses a moment and cannot permit one.

## What the application decides

`MayInstallNow` is called once the installer has been downloaded and verified and the machine-free
rule has passed, immediately before the installer is started. Answering
`InstallMoment.NotNow("a job is running")` stops that attempt and nothing further; the next tick asks
again. The answer is about that moment and is never stored, so it is not a setting and there is
nothing to clear. An application that supplies no call accepts every moment.

Why an application says no is its own business — a job it is running, a lid it is waiting on, a
session it does not want to interrupt. The component neither knows nor asks.

## Nothing reaches a screen

The check runs under `UpdateTrigger.Silent`, which returns before the install path is entered. The
flow the policy owns is wired to `SilentUpdatePrompts`, which answers every question with the step
that carries on and draws nothing, so nothing can appear even if a later change routes an install
through it. The installer is started the way `Launch` starts it, with no window and no question.

An application may have both: the person presses the menu item and sees the update window, and the
policy installs in the background when the machine is free. The policy's own flow is separate, so
neither can draw over the other.

## A refusal is logged once per reason

The reason a refusal carries is what the log is keyed on, so a machine in use all afternoon writes
one line and a different cause writes its own. One wording per cause is what makes that work: a
reason with the minutes counted into it would write a line on every tick.

## The machine reading

`MachineIdle` in `ZeroZero.Update` reads how long since the last keyboard or mouse input in this
session and whether the session is locked. It is a measurement and nothing more; the ten minutes
live above it, in the policy. `IMachineIdle` is the seam a test supplies its own reading through, so
no test touches a real session.

A reading that does not come back is no time at all and not locked, and an unknown or unreadable lock
state is not locked, so only the ten-minute rule can then let an installer start. A session that
cannot be read never stands in for an empty chair.

## What a tick says

`UnattendedTick` carries `Disabled`, `NotDue`, `CheckFailed`, `NothingToInstall`, `NotPrepared`,
`Refused`, `LaunchFailed` or `InstallerStarted`, with the reason and the release where there is one.
A verified installer is held between ticks, so a refused moment costs no second download. Once the
installer is running every tick after it answers `InstallerStarted` and does nothing, so a tick
landing while the application is still on its way out starts no second installer.

## What has a test

Each of the four guards has one: the setting, the ten minutes, the moment an application refuses,
and a check that found nothing. **The locked-screen reading has none**, because a test would have to
lock the session; everything above it runs against `IMachineIdle`.

## Nothing to change

No type was removed, renamed or given a new member. Taking 0.12.0 and changing nothing leaves an
application on exactly the behaviour it had. The wiring is in
[`zerozero-update.md`](../../zerozero-update.md) under "Installing without being asked".
