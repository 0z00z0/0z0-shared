**Unattended update passes run one at a time, and an unknown install answer declines.**

**Released** 2026-10-11

**Minor, additive.** Two fields are added. Takes `ZeroZero.Primitives` 0.8.0, `ZeroZero.Win32`
0.9.2, `ZeroZero.Controls.WinUI` 0.10.0 and `ZeroZero.Brand.WinUI` 0.12.1.

## Added

- **`UpdateScheduler.DefaultInitialDelay`** (30 s) and **`UpdateScheduler.DefaultCheckInterval`**
  (24 h). `UpdateOptions` and `UnattendedUpdateOptions` start from them; the values are unchanged.

## Fixed

- Overlapping `TickAsync` calls wait for one another. Two could each launch an installer and call
  shutdown twice.
- A prompt answering a value `InstallChoice` does not name declines and logs, instead of downloading
  and installing.
- A rate-limit refusal is logged by `UpdateService` with the time the limit lifts, so an
  application-supplied release source gets the line as well. `GitHubReleaseSource` no longer writes
  it itself.

## Changed

- `UpdateWindow` is built on the controls package's `ContentSizedPopup`. A first measure of zero
  opens the window at 200 units.
- The guide and `NotPrepared` state that a failed or unverified download under `CheckCadence.Once`
  ends unattended updating for the rest of the process.
