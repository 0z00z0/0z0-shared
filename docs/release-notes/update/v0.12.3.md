## What the guide states now

`zerozero-update.md` carries the same completeness sentence every guide got: the component's own
source and tests need not be read to adopt it. For the update component specifically, the pass
also stated:

- **What `UpdateOptions` validation actually requires** — the owner, name, product name, signer,
  prefix and file name are required and throw on a blank or malformed value — and the request,
  download, initial-delay and check-interval defaults.
- **`Launch` never throws.** Anything that stops it comes back as `Started` false with a `Detail`,
  and only a `Ready` update is launched.
- **The two answers a release gives carry an empty `Detail`**, where the other six outcomes carry
  one for a person to read.
- **`GitHubReleaseSource` and `ShellInstallerLauncher` are the only replaceable pieces** behind
  `UpdateService`, through `IReleaseSource` and `IInstallerLauncher`; `InstallerDownloader` is
  concrete and `DownloadDirectory` is static, so neither can be substituted in a test.
- **The silent prompts' unconditional install** is named as a trap: a flow wired to
  `SilentUpdatePrompts` downloads and starts whatever release it finds, with neither the
  machine-idle rule nor a question to the application — both live in `UnattendedUpdatePolicy`.

## Unchanged

Every public signature, every default, every outcome `UpdateCheckOutcome` and `UnattendedTick`
report, the flow's behaviour, and the three assemblies' dependencies. An application on 0.12.2
sees no difference beyond what it reads in the guide.
