**A self-driven policy can now report every tick.** `UnattendedUpdateOptions.TickReported` is
called with the `UnattendedTick` each pass produces, whatever the outcome — the same record
`UnattendedUpdatePolicy.TickAsync` already returns to a direct caller, and otherwise something only
the scheduler ever saw once the policy was driving itself.

**Released** 2026-09-28

**Patch.** `TickReported` is a new property with a default of `null` that reports nothing, so a
consumer that changes no code keeps exactly its current behaviour. No existing type is given a new
member, nothing is removed or renamed, and no member changes signature.

## What a consumer on 0.12.1 gets

`TickAsync` returns an `UnattendedTick` to whoever calls it directly, but an application that lets
the policy drive itself through `Start()` never calls it: the scheduler calls it internally and
keeps the result. There was no way for that application to see a tick at all, short of reading the
log lines the policy already writes on its own for a refusal or a failed launch.

## What it does now

`TickReported` is called once per tick, from the one place `TickAsync` returns from, so a direct
call and a scheduler-driven one report identically. A callback that throws is logged — under
`nameof(UnattendedUpdatePolicy)` — and never stops the policy or the schedule: the tick it was
reporting already stands, exactly as `UpdateScheduler` already keeps ticking past a check that
throws.

## Verifying it

One test drives the policy both ways: started through `Start()` with a short interval, the callback
receives the same outcome a direct call would see; called directly, a callback that throws on its
first tick still leaves the returned tick correct, leaves exactly one error logged, and does not
stop a second tick from running and being reported in turn. The direct call is what proves the
guard is the policy's own — `UpdateScheduler` already swallows an exception from the check it is
given, so a test driven through `Start()` alone could not tell a missing guard from a present one.

## Unchanged

`UnattendedTick`, every `UnattendedOutcome`, `MayInstallNow`, the machine-free rule, the
once-per-reason refusal log, and the shape of a self-driven policy that supplies no callback. An
application that does not set `TickReported` sees no difference.
