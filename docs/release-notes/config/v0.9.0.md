**A broken settings file is never written over when its quarantine copy fails, and the copy is a
public type.**

**Released** 2026-10-11

**Minor.** One type is added, and a store whose quarantine copy fails now refuses writes it used to
make.

## Added

- **`QuarantineCopy.TryWrite(policy, directory, fileName, content)`** writes the bytes already read
  to a stamped `.bad` copy in the policy's folder, or `directory` when it names none, and prunes the
  oldest copies of that file beyond `Keep`. It returns the copy's path, or null when `Keep` is zero
  or the file system refused the copy, and never throws for a refusal. Both stores use it.

## Changed

- **When `Keep` is above zero and the copy cannot be written, the broken file stays on disk.**
  `SettingsFile<T>` treats the file as unreadable and refuses every write with an `IOException`
  until a read finds it parseable or a copy succeeds. The sectioned store refuses the write with an
  `IOException`.

## Fixed

- A sectioned document holding a member name that is not UTF-8, such as a key saved in a legacy code
  page, is read with replacement characters instead of throwing. The store's constructor no longer
  fails on it, and the migration keeps its promise never to throw. The name's raw bytes are carried
  across unchanged.

## Changed inside, nothing to adopt

- The migration's four public types — `SettingsSectionMove`, `SettingsMigrationRequest`,
  `SettingsMigrationOutcome`, `SettingsMigrationResult` — and `SettingsKeyCaseConflictException`
  sit in files of their own, unchanged in name, namespace and shape.
