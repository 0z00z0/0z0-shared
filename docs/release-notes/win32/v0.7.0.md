**The first release of the Win32 foundation assembly.** `ZeroZero.Win32` is the raw native layer with
no user-interface framework attached: monitor, DPI and taskbar measurements as plain numbers, the
native task dialog and the four message boxes, and dark native chrome for the process. A console tool
can take it as readily as a WinUI application.

**Plain `net10.0`, not `net10.0-windows`, on purpose** — that is what lets a portable project
reference it. Windows-only-ness is declared by an attribute, so calling it from code that might run
elsewhere is a compiler warning, not a build failure and not a runtime guard. No package references
and no project references at all.

## What is in the package

- **`MonitorMetrics`** — the work area and scale of the monitor under the cursor, the primary work
  area, the scale for a window handle, the non-client size of a window, and the scale of the monitor
  the taskbar sits on. **`NativeRect`** carries a rectangle with Win32's own exclusive right and
  bottom edges, and clamps itself into another.
- **`NativeTaskDialog`** — `Show(owner, TaskDialogRequest)`, with `IsAvailable` as the pre-flight.
  **`TaskDialogRequest`** takes a caption, a headline and buttons, and optionally a body, detail, an
  icon, a default button and command links. A line break in a command link's text splits its title
  from its note.
- **`NativeMessageBox`** — information, warning, error and question, the last returning a boolean.
- **`DarkChrome.Apply(DarkChromeMode)`** — dark context menus and native chrome for the process.

## Two things to know before taking it

**The task dialog needs the consuming application's manifest, and a package cannot supply one.**
Without a `Microsoft.Windows.Common-Controls 6.0.0.0` dependency in the application manifest the
entry point is not there; `Show` says so by name rather than failing obscurely, and `IsAvailable`
answers the question first. The build kit's manifest template declares it.

**Failure yields a usable answer rather than an error.** The primary work area falls back to a
1920×1040 rectangle, every scale falls back to 1.0, and the non-client size falls back to zero — so
nothing here returns an empty rectangle to centre against or a zero to divide by, and nothing here
tells the caller it failed. `NativeMessageBox` is the exception: a message box that never appeared
raises rather than reading as a dismissal.

**Dark chrome is unsupported by construction** — two uxtheme entry points reached by ordinal and
documented nowhere. `Apply` returns false on a Windows build before 10.0.18362 and the chrome stays
light. The rest of the assembly's floor is Windows 10 1809.

## Deliberately not here

Which monitor a window should go on, and the wording of any dialog. Both are the caller's.

## Why 0.7.0 and not 0.1.0

Every component in the family starts at 0.7.0. Up to and including 0.6.0 one number released every
package together; 0.7.0 and above means a component releases on its own.
