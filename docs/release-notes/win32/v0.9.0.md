**A window opened on top of one that dismisses itself on focus loss no longer closes it.** One new
type, and nothing else here moves.

**Minor.** `TransientWindows` is added; no public member changes and none is removed.

## The count

A window that closes the moment it loses focus — the shared About window is one — cannot tell the
reader clicking away from the reader opening a second window of the same application. It reads both
as looking elsewhere, so pressing a button that opens something closes the window holding the
button, in the one gesture.

`TransientWindows` is a count of the application's own short-lived windows:

```csharp
// While the window is up:
IDisposable open = TransientWindows.Enter();

// In the self-dismissing window's deactivation handler:
if (TransientWindows.AnyOpen) return;
```

The count is process-wide and thread-safe, and a scope decrements exactly once however many times
it is disposed — a window can be closed twice, and a count that went negative would disarm every
self-dismissing window for the life of the process.

## What it deliberately does not do

A window deactivated while a transient was open is **not** re-examined when the last one closes. It
stays open until the reader looks away again. A window outstaying its welcome by one glance is a
smaller fault than one vanishing mid-update, and re-examining would mean guessing, from a
deactivation that has already happened, whether the reader meant to leave.

## What a consumer has to change

Nothing, unless it has a window of its own that closes on focus loss. Such a window asks
`TransientWindows.AnyOpen` before dismissing, or it closes under anything the application opens on
top of it.

Nothing counts itself automatically. A window that wants to hold the windows beneath it open calls
`Enter()` and disposes the scope when it closes.

## Verifying it

Proved by running, through the repository's harness: the About window with an update window opened
on top of it stayed open, and with a control window that counts itself among nothing it closed. The
control is what says the measurement can fail.

## Unchanged

`MonitorMetrics`, `NativeRect`, `NativeTaskDialog`, `NativeMessageBox`, `DarkChrome`, the manifest
dependency and the assembly's plain `net10.0` target.
