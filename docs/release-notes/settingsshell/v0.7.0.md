**The first release of the settings window shell.** `ZeroZero.SettingsShell.WinUI` is the settings
window both applications converged on, with every page left to the application: Mica chrome with the
system title bar painted for the theme, a left navigation pane with a product footer, one scroll
viewer over the pages, placement against the application's saved rectangle, Escape to close, and a
section lifecycle.

**It imposes no page vocabulary.** A page built on the shared settings rows and one built on anything
else are hosted alike.

## What is in the package

- **`SettingsWindow`** — built from a **`SettingsWindowSetup`**: a title, the sections, an optional
  starting section, a theme, a place to save the window rectangle, the default size, the pane width,
  a maximum page width, the page padding, and the product name, mark and version for the footer.
  Every measurement is in device-independent units.
- **`SettingsSection`** — a tag, a label, and a function that builds the page. Optionally an icon, an
  enter hook, a leave hook, and a flag saying the page is built once and kept.
- **`IWindowRectStore`** — load and save the window's rectangle, in physical pixels. Where it is kept
  is the application's business.
- **`FitToPages()`** — size the window to what the pages actually need.

## Four things to know

**Pages are built eagerly, in declaration order**, not on first visit.

**A section marked build-once refuses a targeted rebuild.** Rebuild everything and let the flag
exempt it; asking for that one section by name is a mistake worth naming rather than ignoring.

**The page builder and both hooks are the application's code, and their exceptions propagate** — from
the constructor for the builder, from navigation for the hooks.

**Escape closes the window from any control that does not take Escape first.** A flyout or a drop-down
does; a text box does not.

A teardown that must run whichever section is showing belongs on the window's `Closed`, not on a
section's leave hook. And a section list kept and reused must hold only functions — icons and builders
are reusable, built elements are not.

## What it depends on

One project reference, `ZeroZero.Controls.WinUI`, for the title-bar theming and the monitor metrics
that place the window — so a reference on the shell brings the controls assembly, `ZeroZero.Win32` and
the Community Toolkit settings controls with it. Plus the Windows App SDK.
`net10.0-windows10.0.26100.0`.

## Why 0.7.0 and not 0.1.0

Every component in the family starts at 0.7.0. Up to and including 0.6.0 one number released every
package together; 0.7.0 and above means a component releases on its own.
