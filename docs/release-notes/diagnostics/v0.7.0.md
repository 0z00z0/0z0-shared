**The first release of the crash diagnostics component.** Two assemblies that make a crash leave a
trace. `ZeroZero.Diagnostics` catches what nothing else caught, routes it to one place, writes it to a
file that never throws, and puts the version line at the top of every run.
`ZeroZero.Diagnostics.Dumps` turns on Windows Error Reporting's local dumps for one executable and
keeps that registration tidy over the life of a product.

**One reference on `ZeroZero.Diagnostics` adopts both.**

## What is in the package

- **`CrashHandlers`** — registers for the two exceptions nothing else sees, the unhandled one and the
  unobserved task one, and routes both plus the host's own reports to one place. Disposing
  unregisters.
- **`CrashLineAppender`** — the file a crash reaches when everything else has failed. It appends and
  **never throws**: a write that cannot happen returns false. It is itself a log sink, so it can serve
  as the sink before the host's own logging exists. Only its constructor raises, on a path it cannot
  use.
- **`StartupVersionLine`** — the one line that says which build wrote the log, and the assembly's
  name alone when the assembly carries no version.
- **`DumpPolicy`, `DumpRegistration`, `DumpRetention`** — the executable, the directory, mini or full,
  and how many to keep; arm, disarm, read, and prune.

## Three things to know

**Arming a dump registration writes the machine hive, so it needs an elevated process.** A
registration written under the user hive is accepted by the registry and produces no dump at all —
which looks like success and is not.

**A process whose error mode suppresses the fault dialog never reaches Windows Error Reporting.** That
mode is inherited, and a build server's job shell is a common source of it, so a dump that works on a
desktop can be silently absent under automation.

**The shared local-dumps key turns dump collection on machine-wide by its mere existence.** Removing a
product's own entry therefore also removes that key when nothing else is left under it.

## Deliberately not here

No logging framework, and no dump policy default. The two applications this component came from chose
differently, and a default would have overridden one of them. Nor does this component decide whether
the user-interface framework treats an exception as handled — that stays with the application.

## What it depends on

`ZeroZero.Primitives` for the log sink, and nothing else. No third-party package. Both assemblies
target plain `net10.0`; the dumps assembly is Windows-only by attribute rather than by framework, so a
portable console tool can reference it.

## Why 0.7.0 and not 0.1.0

Every component in the family starts at 0.7.0. Up to and including 0.6.0 one number released every
package together; 0.7.0 and above means a component releases on its own.
