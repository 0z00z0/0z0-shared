**An exception reported before an application has finished starting can end the process instead
of leaving it running without a window or an icon.**

**Released** 2026-10-10

**Minor.** Members are added. Nothing an application already calls behaves differently.

## Why

An application started at sign-in can throw before it has finished starting, for instance from a
window opened before the shell is ready. A host that reports the exception and marks it handled
keeps a process with no window and no icon that holds its single-instance lock, so every later
launch is refused until the process is killed by hand.

## The startup window

- **`CrashHandlerOptions.OnStartupFailure`** — the application's cleanup. Setting it opts in.
- **`CrashHandlers.MarkStartupComplete()`** — called once the application is fully up; closes the
  window.
- **Inside the window, `Report` logs the exception, runs the cleanup and calls
  `Environment.Exit(CrashHandlers.StartupFailureExitCode)`**, which is 1. A cleanup that throws is
  logged under `CrashHandlers.StartupFailureSource`, and the process ends anyway.
- **The two process-wide arms are not affected.** An unhandled exception still ends the process the
  runtime's way, and an unobserved task exception is still only logged.
- **With `ProcessLifecycle` armed, the exit is relaunched within its limit.** `MarkDeliberateExit()`
  in the cleanup prevents that.

[`zerozero-diagnostics.md`](../../zerozero-diagnostics.md) has the wiring under "Ending a failed
start".

## What a consumer has to change

Nothing is required. An application that adopts the window sets `OnStartupFailure` when it
registers and calls `MarkStartupComplete()` at the end of its startup.

## Unchanged

With `OnStartupFailure` left null, `Report` only logs, as before. `ZeroZero.Diagnostics.Dumps`
releases under the same number with no change of its own.
