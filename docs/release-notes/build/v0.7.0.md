**The first release of the build kit.** `ZeroZero.Build` is the build machinery every repository in
the family shares: the language and studio-identity settings, the unpackaged WinUI application block
as one import, the application manifest written at build time from a token template, the signing
script with its publish-time target, and the third-party pins under central package management.

**It is the one package with no assembly.** Nothing is compiled into it and it declares no
dependencies; what it carries is MSBuild files, a manifest template and a PowerShell script.

## It is taken as an MSBuild SDK, not as a package reference

**A `PackageReference` to it is a build error, deliberately.** NuGet settles central package
management before restore runs, and a package's files arrive after — so the reference would restore
cleanly and apply nothing at all. The kit turns that silence into an error naming the three imports
that do work.

Taking it means accepting the pin rule. A family package resolving at another version, or declared
twice, fails the build; a project opting out of central package management fails the build; version
overrides are switched off, so NuGet itself refuses one. **A repository that needs a newer family
package raises it here and takes the kit's next release** — there is no local escape hatch, and that
is the point.

Two of the pins are ceilings rather than preferences. An application holding a direct reference
*below* one it also gets transitively is a NuGet error, so the notify-icon library and the Community
Toolkit settings controls are raised in the kit or not at all.

## What is in the package

- **The shared settings** — latest language version, nullable reference types, implicit usings,
  en-GB as the neutral language, and the studio's author, company and copyright.
- **The pins** — the Windows App SDK, the SDK build tools, the Community Toolkit settings controls,
  the notify-icon library, the MQTT client, the Task Scheduler library, the system-events package,
  and the test tooling.
- **The WinUI application block** — output type, target framework and platform floor, unpackaged
  packaging, the runtime identifier taken from the process architecture, en-GB as the default
  language, and the manifest wiring. Everything in it is a default a project may override except the
  packaging kind: anything but unpackaged fails the build.
- **The manifest template** — two tokens, the assembly name and the execution level. It declares
  Windows 10 and 11 support, per-monitor v2 DPI awareness, and the common-controls dependency the
  Win32 layer's task dialog needs.
- **The signing script and its post-publish target.** The certificate password reaches the script
  through an environment variable, never as an argument. It needs PowerShell 7 on the path.

Every refusal has a code, so a build that stops says which rule it broke.

## Deliberately not here

**The source-revision stamp**, which a reader will look for. It belongs to `ZeroZero.Primitives`,
because it is the build half of that assembly's version reader. The kit neither carries it nor
imports it.

## Why 0.7.0 and not 0.1.0

Every component in the family starts at 0.7.0. Up to and including 0.6.0 one number released every
package together; 0.7.0 and above means a component releases on its own.
