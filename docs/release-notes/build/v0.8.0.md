**A signing run that cannot timestamp now fails the build instead of shipping.** One guard, its
error code, and the corrections to what the script and the guides claimed.

**Minor.** Nothing recompiles and no property changes name, but a publish that used to go green can
now go red — on exactly the days it was producing a signature with a shelf life.

## What was shipping

Signing against a timestamp authority that could not be reached, or one that answers only the newer
protocol, produced a **correctly signed file carrying no timestamp**, and the script printed its
success line and exited zero. Measured against both: the file that came out was indistinguishable
from one signed with `-NoTimestamp` — same status, same signer, an empty unsigned-attribute set in
its certificate table.

**An untimestamped signature stops verifying when the certificate expires.** A timestamped one keeps
verifying for the life of the timestamp. So a release signed on a day the authority was unreachable
looked correct on the day it shipped and would have failed for everyone who had already installed
it, on a date nobody chose.

The signing call's return value was discarded, and the read-back that followed proved the signer and
the trust status without ever looking for the countersignature.

## What it does now

The read-back asserts the countersignature. A file that comes back signed and untimestamped fails
with `ZZS013`, naming the authority that did not answer and the switch that declines a timestamp
deliberately. Both timestamp schemes satisfy it: what is asserted is that the file is timestamped at
all, not which envelope carries it.

The success line now says which authority timestamped the file, or that none was asked for, so a
build log carries the evidence rather than only the claim.

## Also corrected

- **The script's own help** said the file is timestamped unless timestamping is switched off. It now
  says what happens when the authority does not answer.
- **`ZeroZeroSignTimestampServer`** in the build guide now says the build fails rather than
  shipping untimestamped, and that `ZeroZeroSignNoTimestamp` is the only remaining way to produce an
  untimestamped signature.
- **The build-kit checklist** entry for the single timestamp server now says what a run that reaches
  no authority produces, and why it is refused.

## Beside this, outside the package

Release verification asserts the same thing independently, on the executables it fetches from the
feed under `-Signer`. That check runs on the published file rather than on the machine that signed
it, so it also catches an artefact this script never signed. It reaches a consumer through the
workflow tag, not through this package.
