**The first release of the controls foundation assembly.** `ZeroZero.Controls.WinUI` holds the WinUI
controls that carry no studio identity: the settings-row vocabulary — info bubble, section header,
card row — title-bar theming, and a single-line text prompt. **No font pack, no palette, no theme
keys**, so any component can take it without dragging a visual identity along.

**It is where the info bubble now lives.** A consumer that used `ZeroZero.Brand.WinUI.InfoIcon` takes
this package instead and changes the namespace; the control is otherwise unchanged, and the brand
component's own notes carry the detail.

## What is in the package

- **`InfoIcon`** — the (i) button whose explanation opens in a **flyout rather than a tooltip**, so
  several sentences survive the pointer moving away. It is a real button, so Space and Enter open it
  without extra work, and its glyph names both the Windows 11 and Windows 10 icon fonts.
- **`SettingsSectionHeader`** — a heading with an optional bubble and divider, and a slot for
  trailing content. The bubble appears only when there is text for it, and takes the heading as its
  subject when none is given.
- **`SettingsRow`** — a header, a description and a field, with an optional bubble. **The bubble sits
  to the left of the field**, which is the alignment contract: a row with a bubble and a row without
  share the same right edge.
- **`TitleBarTheming`** — `Apply` paints the system title bar for a theme, `Follow` keeps it in step.
  **`TitleBarPalette`** carries the twelve caption colours, with a dark and a light set built in.
- **`TextPromptWindow`** — a modal single-line prompt, awaited through `ShowAsync`, with the caption,
  message, note, placeholder, length cap and empty-input rule all on its options record.

## Two things to know

**Title-bar theming is one-way.** A bar that has been painted once cannot be handed back to the
system — setting its colours to null afterwards draws it black. So an untouched bar on a light theme
is left alone, and a bar that was dark is repainted with the light set. A custom palette replaces the
dark set only and is never applied to a light bar.

**The row inherits the toolkit card's own wrap.** Below roughly 476 device-independent units the
field drops beneath the header, and that is driven by the card's width, not the window's.

## What it depends on

The Windows App SDK, the Community Toolkit's settings controls, and `ZeroZero.Win32` — the last for
placing the prompt window on the right monitor. **No toolkit type reaches a public signature**: the
row wraps the toolkit's card privately rather than deriving from it, so a toolkit upgrade is never an
API change here. The toolkit pin is a ceiling for a consumer's own direct reference to the same
package.

## Why 0.7.0 and not 0.1.0

Every component in the family starts at 0.7.0. Up to and including 0.6.0 one number released every
package together; 0.7.0 and above means a component releases on its own.
