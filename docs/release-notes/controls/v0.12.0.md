**The WinUI controls move to .NET 11 and Windows App SDK 2.7.0.**

**Released** 2026-11-19

**Minor, breaking.** The packages target `net11.0-windows10.0.26100.0` instead of `net10.0-windows10.0.26100.0`, and the Windows App SDK under them moves from 2.4.0 to 2.7.0. No type, member or behaviour changes. Takes `ZeroZero.Win32` 0.10.0, `ZeroZero.Primitives` 0.10.0 and `CommunityToolkit.WinUI.Controls.SettingsControls` 8.2.251219.

## What a consumer has to change

- Target `net11.0-windows10.0.26100.0`, which the build kit's application block at 0.10.0 sets, and
  build with the .NET 11 SDK, 11.0.100 or later.
- **The Windows App SDK moves from 2.4.0 to 2.7.0.** An unpackaged application needs
  `Microsoft.WindowsAppRuntime.2` at 2.7.0.0 registered for the user; an installer that carries the
  runtime, and any prerequisite check written against 2.4.0, move to 2.7.0 with it. A self-contained
  publish carries the runtime in its own folder.
- A direct reference to a component named above rises to at least the version named, or the restore
  fails with `NU1605`.
- Raise `ZeroZero.Build` to 0.10.0 in the same change where the application takes the build kit.
  The kit pins the packages named above; an older kit pins them below what this release needs, and
  the restore fails with `NU1605`.
- **The .NET 11 desktop runtime is required on the end user's machine** for a framework-dependent
  application; a self-contained publish carries it.
