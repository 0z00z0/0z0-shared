**A popup window sized to its own content.** One new type and its options, and one new reference.

## Added

- **`PopupWindowFit`** and **`PopupWindowFitOptions`** — a window grown to the height its content
  measures, capped at a share of the work area and centred on the monitor it is on. The caller
  hands over the window, the scroller's content panel and the options — fixed width, floor,
  scroller padding, the share to stop at, a name for the line it writes, and the log sink — and
  calls `FitToContent()` whenever the panel lays out.
  - **The first activation arrives before the first layout pass.** A call with nothing laid out yet
    does nothing and says so once; a call whose answer has not moved does nothing at all. So a
    window that raises layout repeatedly is resized once per open rather than once per pass.
  - The panel's own height is read, not the scroller's viewport: the panel's height is independent
    of the window's and is final after the first layout, so no second pass at the final size is
    needed.
  - The monitor is found from the centre of where the window already sits, and a centre on no
    monitor answers for the nearest one, so a popup opening off the desktop still lands somewhere
    reachable.

The arithmetic itself is `ZeroZero.Win32.WindowFit`, new in `win32` 0.9.1. An application sizing
something other than a popup calls that directly.

## What a consumer on 0.7.0 gets

Nothing it had changes, and no control's markup or behaviour moves.

**One new package dependency.** `ZeroZero.Controls.WinUI` now references `ZeroZero.Primitives`, for
`ILogSink` alone. An application taking the MQTT module, the diagnostics, lifecycle, startup or
update components already resolves that package, and one taking the controls assembly on its own
resolves it transitively from here. A consuming repository reading from the studio's feed needs the
`ZeroZero.Primitives` read grant if it did not already have one; the restore stops with a 403 on
that package name and nothing else if it does not.

`controls` therefore releases after `primitives` as well as after `win32`.
