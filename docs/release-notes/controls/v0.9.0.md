**A window can hide itself from the taskbar and Alt+Tab before the taskbar exists without ending
the process.**

**Released** 2026-10-11

**Minor.** One type is added. Nothing an application already calls behaves differently.

## Added

- **`SwitcherVisibility.TrySet(appWindow, shown, log)`** sets `AppWindow.IsShownInSwitchers` and
  returns false instead of throwing where Windows refuses for want of a taskbar.
  - **The plain setter throws `NotImplementedException` ("SetShownInSwitchers failed") while no
    taskbar window exists**, as at sign-in before Explorer has created it. Measured on Windows App
    SDK 2.4.0 on a desktop with no taskbar, and reported on 2.5.1. From a window's constructor, that
    throw ends the process.
  - On that refusal the window stays as it was in the taskbar and Alt+Tab, and one line is written
    to `log` the first time in the process. Nothing retries the call later.
  - Any other exception propagates. `log` is optional; without one nothing is written.

## Fixed

- `TextPromptWindow` sets its switcher visibility through `TrySet`, so a prompt opened before the
  taskbar exists no longer ends the process.

## What a consumer has to change

Nothing is required. An application's own window that sets `IsShownInSwitchers` directly can call
`TrySet` instead; [`zerozero-tray.md`](../../zerozero-tray.md#the-startup-rule) has the rule that
still applies: no window before the tray icon exists.
