**An application's own buttons in the About row, a bracket action button, a brand orange, and the
brand typeface in a published application.**

**Released** 2026-09-14

**Minor.** Everything is additive: no public member is removed, renamed or changed in meaning. One
change reaches the screen of every application on this component without it opting in: the About
row reads Website, Donate, What's new, each button at its natural width, where it read What's new,
Website, Donate in three equal columns.

## The typeface reaches a published application

A self-contained publish of an application on the package route carried no brand typeface. The
Windows App SDK tooling copies the files a referenced library's `.pri` lists into the build output
and nowhere else, so the font and its licence reached the build folder but not the publish folder,
and the About surface fell back to whatever face the machine had.

The package now carries `buildTransitive\ZeroZero.Brand.WinUI.targets`, which adds both files to the
publish set at the path the markup names, `ZeroZero.Brand.WinUI\Assets\Fonts\`. It adds nothing to a
build, whose copy is unchanged, and it skips a file whose path the publish already holds, so a
toolchain that starts publishing them itself meets no duplicate. A package that stops carrying both
files fails the consuming publish with an error naming them, rather than publishing without the face.
Nothing changes in a consuming project: the targets file arrives with the package.

Measured with a scratch application on the package route, Windows App SDK 2.4.0, built with
`dotnet build -c Release` and published with `dotnet publish -r win-x64 --self-contained`:

| Package | Build output | Publish output |
|---|---|---|
| 0.8.0 | font and licence | **neither** |
| 0.9.0 | font and licence | font and licence |

All four runs finish with no warning and no error. A publish on the sibling-checkout route, where the
files are the library's own content items rather than package files, is not measured.

## An application's own buttons in the About row

`AboutInfo` gains `Buttons`, a list of `AboutButton(Label, OnClick)`. Each becomes a button at the
end of the row, in the row's own style — the brand face at the row's size — with the label as its
text and accessible name, and the action run on every press.

```csharp
Info = new AboutInfo
{
    AppName     = "ExampleApp",
    Version     = "1.2.3",
    Description = "What the app does.",
    RepoUrl     = "https://github.com/0z00z0/ExampleApp",
    Buttons     = [ new AboutButton("What's new", () => new WhatsNewWindow().Activate()) ],
};
```

The row reads **Website / Donate / What's new / the application's buttons**. The built-in What's new
still appears only when `ReleaseNotesUrl` is set. The buttons arrive the same way through
`BrandAboutWindow`, from `BrandAboutOptions.Info`, and through a page that calls `SetInfo`; calling
`SetInfo` again replaces the application's buttons rather than adding to them.

**The row wraps and closes up.** Buttons sit left to right at their natural widths and move to a
second line when the next one does not fit. A hidden button takes neither width nor a gap, so an
application without `ReleaseNotesUrl` no longer shows an empty third of the row.

## A bracket action button

`BrandBracketButton` is a borderless button for a host to place on its own — a "Check for updates"
under the About card, say. The logo's square brackets stand at either end in the logo's teal-to-blue
gradient, a `>` chevron in the brand orange leads, and the label follows in the brand face. It
carries its own colours and face, so no dictionary has to be merged for it.

The host sets `Label` and `State` and handles `Click`:

| `BrandBracketButtonState` | Shows |
|---|---|
| `Rest` | The chevron and the label. |
| `Busy` | A text spinner cycling `\| / - \` in place of the chevron; the brackets breathe. |
| `Success` | The brand slashed zero in place of the chevron, teal brackets and label; back to `Rest` after four seconds by itself. |
| `Attention` | Amber brackets and label, held until the host sets another state. A press raises `Click` as usual. |

Hover spreads the brackets 3 px and a press closes them 2 px. Hover and keyboard focus show a block
caret after the label, blinking; in `Attention` the caret shows dimmed at rest as well. With the
system's animation effects off, nothing blinks, spins or moves, and the spinner is a still ellipsis.
Underneath is an ordinary `Button`, so Tab, Enter, Space and the focus rectangle are the platform's,
and the accessible name is the label.

**Text contrast clears 4.5:1 in both themes.** The button has no fill, so every figure is against
the surface under it: WinUI's base window background and its default card fill over that, `#202020`
and `#2b2b2b` in dark, `#f3f3f3` and `#fbfbfb` in light. The palette's own teal, amber and orange
measure between 1.5:1 and 2.7:1 on a light window, so the light theme takes a darker shade of each,
same hue and saturation:

| Used for | Dark | Window / card | Light | Window / card |
|---|---|---:|---|---:|
| Chevron | `#e0872a` | 5.95 / 5.17 | `#985916` | 5.01 / 5.37 |
| Spinner, caret, `Success` label and brackets | `#27e0c8` | 9.76 / 8.48 | `#117568` | 5.02 / 5.39 |
| Slashed zero, `Attention` label, brackets and caret | `#d8a657` | 7.38 / 6.41 | `#896120` | 4.99 / 5.35 |
| Bracket gradient, lower stop | `#11a9d6` | 5.95 / 5.17 | `#0b718f` | 5.02 / 5.38 |

The label at rest takes `TextFillColorPrimaryBrush`. High contrast replaces every brand colour with
the system highlight colour, as `BrandResources.xaml` does.

## A brand orange

`Brand.ColorOrange` is `#e0872a`, and `BrandResources.xaml` carries it as `BrandOrangeColour` and
`BrandOrangeBrush`: the same value in light and dark, the system highlight colour in high contrast,
like every other accent. It measures 7.01:1 on the brand background, 6.64:1 on the alternate one,
7.67:1 against black and 2.74:1 against white, so it takes black text like every accent but Indigo,
and as a 24 % tint it reaches 1.44:1 and 1.46:1 on the two grounds. The palette tests pin all four
figures.

## Unchanged

`BrandAboutControl.SetInfo`, `CancelPendingFetch` and `ContentResized`, `BrandAboutWindow`,
`BrandAboutOptions` with its two callbacks, `ExternalLibrary`, `ConsoleBanner`, the nine existing
colour keys with their brushes, and the theme behaviour. `ZeroZero.Brand.Core` gains `AboutButton`,
`AboutInfo.Buttons` and `Brand.ColorOrange`, and releases under the same number.
