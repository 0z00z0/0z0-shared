**The bracket action button carries its own symbol, and several of them can share one width.** Two
additions the update window needed and any host can use, plus the About window holding its
dismissal while a window of the same application is on screen.

**Minor.** Members are added and none change or go, so a button written against 0.9.2 renders
exactly as it did.

## A symbol per button

Every bracket button showed the same `>` chevron, whatever it did. `Symbol` is one plain character
before the label — a down arrow for a download, a cross for a stop, a tick for read-and-done,
whatever the act is:

```xml
<brand:BrandBracketButton Label="Install now" Symbol="&#x2193;"/>
```

A plain character in the brand face rather than a picture, so it takes the theme and the display
scaling the rest of the button takes, and it needs no asset. A chevron where the host names none.

**Pick one the face carries.** Cascadia Mono covers 1483 code points, and `↗` and `✕` are not among
them; a character it lacks is drawn by whatever font Windows falls back to, which is a different
shape and weight beside the label. Measured as present: `↓`, `→`, `»`, `×` and the default `>`.
`✓` is in the face too and was tried, but this face draws it close to a square-root sign and it
reads as "done" rather than "close", so the update window uses the cross for both.

Only `Rest` and `Attention` show it. The text spinner and the slashed zero take its place while
`Busy` and `Success` are showing, exactly as they took the chevron's.

## One width for several buttons

A bracket button sizes itself to its own text and centres itself in whatever width it is given, so
a stack of three sits at three different lengths with their brackets nowhere near each other.

`BrandBracketButtonColumn` stacks them and gives every one the width of the widest:

```xml
<brand:BrandBracketButtonColumn Spacing="2" HorizontalAlignment="Center">
    <brand:BrandBracketButton Label="Install now" Symbol="&#x2193;"/>
    <brand:BrandBracketButton Label="Not now" Symbol="&#x00BB;"/>
</brand:BrandBracketButtonColumn>
```

Each button then spreads its brackets across that width and keeps its symbol and label centred
between them. The column is only as wide as that widest button, so a host centres or aligns the
whole group as one thing rather than one button at a time. A collapsed button takes no width, no
height and no spacing, so a column whose buttons change with what is on screen closes up.

`FillsWidth` is the switch the column throws on each child. A button placed anywhere else never
sees it and is unchanged — which answers the question 0.9.2 raised: a width imposed on the control
moves the button about inside it and has never stretched it.

## The About window's close cross is in the brand face

The cross in the corner was `✕` (U+2715), which Cascadia Mono does not carry, so Windows drew it
from whatever face it fell back to — a different shape and weight in a window that is otherwise one
face throughout. It is now `×` (U+00D7), which the face does carry, and which is the same character
the update window uses for its own cross and its stop button.

## The Donate button's mark is drawn

The hot beverage on that button was U+2615, which the face does not carry either, so it came from a
fallback font as a colour emoji of a fixed design. It is now a path: a tapered cup, a handle open
to the right and a saucer close under it, which scales with the display, takes the theme and is the
studio's own to change.

It is larger than the character it replaces — 17 effective pixels, twice the cap height of the
label beside it — and still inside the button's own minimum height, so the button row does not
grow. The label is unchanged.

The colour is the palette's orange, `#e0872a`, on a dark ground; that orange is too pale on a light
one, so light takes `#895014`, the darker shade of the same hue `BrandBracketButton` already uses.
Measured off the captured pictures, mark against the button's own fill: **6.14:1 on light** and
**5.03:1 on dark**, either side of a mark that would glare or disappear.

## The About window holds its dismissal

`BrandAboutWindow` closes the moment it loses focus, which meant that pressing its own "Check for
Updates" button opened the update window and closed the About window under it, in the one gesture.
It now ignores a deactivation while a transient window of the same application is on screen —
`TransientWindows.AnyOpen`, from `ZeroZero.Win32` 0.9.0, which this release requires.

A window deactivated while a transient was open is not re-examined when the last one closes, so it
stays open until the reader looks away again.

## What a consumer has to change

Nothing. Every addition is optional and the defaults are what 0.9.2 did.

`ZeroZero.Win32` 0.9.0 has to be on the feed first: the About window's guard is a call into it.

## Verifying it

Proved by running, through the repository's harness and the pictures in
[`zerozero-update.md`](../../zerozero-update.md), which is where the symbol and the column are on
screen: the same window in seven states, light and dark. Measured separately: the About window
survived an update window opening on top of it and closed under a control window that counts itself
among nothing.

## The pictures

The About pictures are now taken in both themes, so `Capture 'About' screenshot.ps1` writes
`about-window-light.png`, `about-window-dark.png`, `about-hosted-control-light.png` and
`about-hosted-control-dark.png` in place of the two it wrote before. The two it replaces were
captured before 0.9.0 and showed a button row that has since changed, so they were removed rather
than left standing for a window they no longer match.

## Unchanged

`BrandAboutControl`, `BrandAboutOptions`, `AboutInfo`, `Brand.cs`, the palette, the typeface and
every animation timing. `BrandBracketButtonState` is unchanged. Both brand assemblies release under
the same number.
