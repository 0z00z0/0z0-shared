**The info bubble has left the brand assembly**, the palette and the brand typeface are now a
resource dictionary XAML can merge, and two colours join the palette. **A consumer using
`ZeroZero.Brand.WinUI.InfoIcon` must change a reference and two namespaces** — that is the whole of
the break, and the control itself is unchanged.

**Minor rather than patch.** A public control is gone from this assembly, and a reference now brings
a different set of assemblies with it.

## The info bubble moved out

`InfoIcon` — the little (i) button whose explanation opens in a flyout — is now
`ZeroZero.Controls.WinUI.InfoIcon`, in the new controls foundation assembly. **Nothing about the
control changed**: the same `Info`, `Subject` and `GlyphCode` properties, the same fallback glyph, the
same composed screen-reader name.

What a consumer does:

- Add a reference on **`ZeroZero.Controls.WinUI`** at 0.7.0.
- Change the markup namespace from `using:ZeroZero.Brand.WinUI` to `using:ZeroZero.Controls.WinUI`.
- Change the C# `using` the same way.

**Why it matters beyond the rename.** The bubble is settings-row furniture with no studio identity in
it, and it was sitting in the assembly that ships the studio's typeface, palette and About window.
Anything that wanted one bubble took all of that. It now lives where a control with no identity
belongs, and **a reference on the brand component is once again a reference to the studio's identity
and nothing else** — which is the thing to weigh when deciding whether to take this component at all.

The MQTT settings panel dropped its brand reference in the same change, so taking that panel no
longer brings the brand assemblies and the font pack along. An application that wants the About
control now references this component deliberately.

## The palette and typeface as a resource dictionary

`Themes/BrandResources.xaml` can be merged into an application's resources once and then resolved per
key, so markup no longer has to reach for a constant in code.

It carries **nine colour keys and a matching brush for each**, plus `BrandFontFamily`. Light and dark
resolve to the same literal values — the identity does not follow the theme. **High contrast resolves
every ground and accent to the system's own colours**, so the palette never reaches a high-contrast
screen.

The dictionary is addressed through the library's own path; the font is addressed through the
consuming application's output root, which is where the packed font lands.

## Steel blue and terracotta

Two colours join the palette, named for the colour rather than for the job either did in the
application it came from. Both clear 4.5:1 against both palette grounds, comfortably above the floor
the palette already held, so neither is admitted with an exception.

The same change pinned two palette rules that had been folklore: **text on an accent is black**, with
Indigo the single accent that runs the other way; and **a tinted fill is not derived by lowering
opacity** — both grounds sit near black, so at 24 % nothing in the palette clears 1.75:1 against its
ground, and even pure white reaches only 2.17:1.

## What a brand reference now brings

`ZeroZero.Brand.WinUI` takes `ZeroZero.Brand.Core` and, new in this release, **`ZeroZero.Win32`**.
The About window's own copy of the monitor and DPI interop is gone and it now uses the shared Win32
layer, so a brand reference pulls that assembly in transitively. It adds no third-party package.

## What has not changed

`BrandAboutControl` and `BrandAboutWindow` keep their surface: `SetInfo(AboutInfo)` and the
`ContentResized` event on the control, `BrandAboutOptions` on the window. Omitting the
check-for-updates callback still hides that button. `Brand`, `AboutInfo`, `ExternalLibrary` and the
console banner are untouched apart from the two new colour constants.

One correction with no API change: the claim that Indigo cannot reach the 3:1 non-text floor at any
opacity was wrong — it reaches it on the brand background. What is true, and is now asserted in both
directions, is that Indigo is the tightest of the seven accents on both counts: the dimmest tint on
either ground, and the only accent clearing 3:1 without clearing 4.5:1 for body text.

## Taking it

Two packages: `ZeroZero.Brand.Core` on `net10.0`, `ZeroZero.Brand.WinUI` on
`net10.0-windows10.0.26100.0`. Both release together under one tag and one number.
